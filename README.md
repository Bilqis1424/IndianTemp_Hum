# IndianTemp_Hum – Stacked Ensemble Forecasting for Temperature and Humidity

**Multi‑Location Temporal Forecasting of Near‑Surface Temperature and Relative Humidity Across Diverse Climatic Regions of India**

This repository contains the complete, reviewer-responsive pipeline used to produce the results reported in `Methodology_Report.docx`. It resolves all eleven major second-round review comments; see Section 7 of the report for the full comment-by-comment crosswalk.

## Repository contents

| File | Purpose |
|---|---|
| `indian_weather_pipeline_v3_final.py` | Main pipeline: data validation, feature engineering, persistence/ARIMA/LSTM baselines, the time-series-safe stacked ensemble, walk-forward validation, true leave-one-city-out evaluation, SHAP, residuals, and multi-step recursive forecasting. |
| `plot_residuals_standalone.py` | Standalone script producing residual diagnostics for the stacked ensemble (temperature and humidity). |
| `plot_study_cities_forecasts.py` | Standalone script producing the 48-hour recursive forecast figure for all 8 study cities, with a built-in data-integrity guard. |
| `plot_india_weather_map.py` | Standalone script producing the interactive Folium/GeoPandas map of all 543 locations (raw vs. predicted values on click). |
| `Methodology_Report.docx` | Full methodology, results, and reviewer-comment resolution report. |
| `requirements.txt` | Exact package versions used to produce the reported results. |
| `outputs/` | All figures, per-city/per-horizon CSV result tables, and the interactive HTML map generated by the scripts above. |
| `checkpoints/` | Cached intermediate artifacts (prepared data, trained model, per-city ARIMA/LOCO results) enabling the standalone scripts in Option B below to run instantly without retraining. |

## Data source and provenance (Reviewer Comment 9)

The dataset is the **Indian Weather Repository**, publicly available on Kaggle. The raw file used for every result in this repository is `IndianWeatherRepository_raw.xlsx`: 34,466 observations across 543 locations, sampled at ~6-hour intervals from 2023-08-29 to 2023-10-30.

**Provenance of the exact file used in the final reported run:**

- **SHA-256 hash:** `5811ab9d3584e8a83d86c91fe2b9b7004b3a8feb5054c9e605050a83c1ac6792`
- **Recorded date:** `2026-08-16`

> **Note on the date field.** This date is the file's last-modified timestamp at the time of this run, used as a proxy in the absence of a separately recorded acquisition date — it is *not* necessarily the date the file was first downloaded from Kaggle. If you have the true original download date on record (e.g., from your own download history), replace the date above with that value and note the substitution here. The SHA-256 hash, by contrast, is a genuine, verifiable fingerprint of the exact file bytes and will reproduce identically for anyone hashing the same file.

**To independently verify you are working with the identical file**, run:

```bash
sha256sum "csv files/IndianWeatherRepository_raw.xlsx"
```

and confirm the output matches the hash above. The pipeline also recomputes and logs this hash automatically at the start of every run (see `get_dataset_provenance()` in `indian_weather_pipeline_v3_final.py`), so any future re-run against a modified or re-exported copy of the source file will produce a different hash and should be treated as a different dataset snapshot.

## Execution instructions (Reviewer Comment 8)

The full pipeline is compute-intensive — per-city ARIMA order search and true leave-one-city-out evaluation across all 543 locations together take on the order of 20–30 minutes on a standard CPU.

### Option A — full run, single command

```bash
python indian_weather_pipeline_v3_final.py
```

Runs every stage in sequence (data validation → feature engineering → persistence/ARIMA/LSTM baselines → stacked ensemble → walk-forward validation → full 543-city LOCO → SHAP → residuals → multi-step forecasting → all 8 study-city figures) and writes every artifact to `OUTPUT_DIR`.

### Option B — regenerate a single figure or output without a full re-run

Once `checkpoints/data_prepared.pkl` and `checkpoints/stage_b_model.pkl` exist (produced by Option A above), the three standalone scripts each work independently and finish in seconds to a couple of minutes:

```bash
python plot_residuals_standalone.py        # residual diagnostics, both targets
python plot_study_cities_forecasts.py      # all 8 study-city 48h forecast figures
python plot_india_weather_map.py           # interactive India map (raw vs predicted)
```

If the relevant checkpoint is missing, each of these scripts automatically falls back to regenerating what it needs from the raw data file (documented at the top of each script), so they remain runnable from a completely clean checkout — just slower.

### Recommended execution order for a from-scratch reproduction

1. `python indian_weather_pipeline_v3_final.py` (full run — see note above on runtime for the ARIMA/LOCO stages)
2. `python plot_residuals_standalone.py`
3. `python plot_study_cities_forecasts.py`
4. `python plot_india_weather_map.py`

All four together reproduce every figure, table, and number reported in `Methodology_Report.docx`.

### Quick smoke test

For a fast verification (fewer ARIMA/LOCO cities, fewer LSTM epochs — minutes instead of tens of minutes), set `fast_smoke_test=True` inside the `main()` call at the bottom of `indian_weather_pipeline_v3_final.py`:

```python
if __name__ == "__main__":
    main(fast_smoke_test=True)
```

This is intended to confirm the pipeline runs end-to-end without error before committing to a full reported run — the resulting numbers will differ from the results below and should not be cited as reported results. Set it back to `False` (the default) to reproduce the numbers in `Methodology_Report.docx`.

## 📊 Results Summary

Full per-fold, per-city, and per-horizon tables underlying every number below are written as CSV files to `OUTPUT_DIR` by `indian_weather_pipeline_v3_final.py` (walk-forward results, per-city ARIMA order/AIC/accuracy, per-location LOCO results, and multi-step MAE/RMSE/R² by horizon), alongside every figure referenced in `Methodology_Report.docx`.

| Model | Temp R² | Temp MAE (°C) | Temp RMSE (°C) | Hum R² | Hum MAE (%) | Hum RMSE (%) |
|---|---|---|---|---|---|---|
| Persistence | 0.817 | 1.009 | 1.960 | 0.662 | 6.728 | 10.534 |
| ARIMA (per-city, AIC-selected) | 0.069 | 0.810 | 1.089 | -0.061 | 5.727 | 7.694 |
| LSTM | -0.344 | 3.616 | 5.308 | -0.368 | 17.411 | 21.217 |
| **Stacked Ensemble** | **0.933** | **0.801** | **1.184** | **0.786** | **6.336** | **8.386** |

- **Walk-forward validation (5 folds):** Temp R² = 0.935 ± 0.018, Hum R² = 0.898 ± 0.024
- **LOCO (all 543 cities):** median Temp R² = 0.816 (mean 0.685), median Hum R² = 0.834 (mean 0.712)
- **Improvement over persistence (stacked ensemble):** Temp MAE ↓ 20.5%, RMSE ↓ 39.6%; Hum MAE ↓ 5.8%, RMSE ↓ 20.4%

See `Methodology_Report.docx` Section 6 for full interpretation of each result, including why ARIMA and LSTM post near-zero or negative R² despite comparatively modest MAE (a target-variance effect, not a contradiction), and why humidity is intrinsically harder to forecast than temperature at several coastal locations.
