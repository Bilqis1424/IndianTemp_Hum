What changed relative to indian_weather_pipeline_v3_final.py (why the numbers below differ from the previous README)
The ARIMA-corrected pipeline was produced in direct response to the two outstanding points in the most recent review round. Two substantive changes were made; both are documented in more detail in Section 7 of the report.

Change 1 — Fair ARIMA evaluation (responds to "ARIMA needs investigation/clarification").
The previous ARIMA result (Temp R² = 0.069, Hum R² = −0.061) was an evaluation artefact, not a property of ARIMA on this data. Two problems existed in the old pipeline:

ARIMA was fitted and evaluated on the raw per-city series with its own train/test split, which did not coincide with the split used by persistence, LSTM, and the stacked ensemble.

The aggregate ARIMA metric was reported as the mean of per-city R² values, whereas persistence and the stacked ensemble were reported as pooled R² over the full held-out set. Averaging R² across 543 cities — many of which have short, low-variance test windows — biases the aggregate sharply downward even when the underlying predictions are of comparable quality.

ARIMA is now evaluated on exactly the same held-out rows as every other model (the train/test boundary is defined by intersecting each city's series with the same test index used downstream), and its metrics are reported pooled over those rows, in original physical units (°C and %RH). Row-level predictions with city, datetime, y_true, and y_pred are saved so the alignment can be verified independently. After the correction, ARIMA's temperature R² rises from 0.069 to 0.926 and its humidity R² from −0.061 to 0.797 — comfortably in line with the persistence and stacked-ensemble baselines, and the best model on humidity R².

Change 2 — Fair persistence baseline. The previous persistence baseline used a single global shift(1) on the concatenated multi-city test set, which for the first row of each city predicted from the last row of a different city. That cross-city contamination made persistence look artificially worse than it should. In the corrected pipeline, persistence is computed per-city (yhat_t = y_{t-1} within the same city), and the corrected persistence MAE is therefore stronger — 0.783 °C instead of 1.009 °C — which is why the stacked ensemble no longer shows a large MAE advantage over persistence. This is an honest correction; the manuscript now states plainly that the stacked ensemble matches but does not beat per-city persistence on temperature MAE, and that its advantage over ARIMA is confined to a small RMSE reduction on temperature.

Three additional improvements were also made to the feature set and modelling pipeline: (a) extended temporal features (lags 1–8, rolling means/stds over 24h and 48h, 24-hour change, lagged atmospheric covariates); (b) per-city additive bias correction, fitted on a chronological validation slice and shrunk toward zero; (c) three clearly-labelled R² definitions reported side by side (pooled, per-location with bootstrap CIs, and R²_anom — a within-city skill score against a per-city climatological mean). The three-way R² distinction is what prevents a recurrence of the graphical-abstract mismatch flagged in the previous review round.

Three complementary R² definitions
Three R² definitions are reported side by side because they answer different questions on different denominators. They are not interchangeable, and the manuscript labels each explicitly:

Pooled R² — evaluated on the full held-out set (the main comparison table above). Reflects both cross-city climatic separation and within-city temporal skill.

Per-location R² — within-city R², reported with 95 % bootstrap CIs, in per_location_*_temp.csv / per_location_*_hum.csv and their *_study_cities.csv subsets. Reflects within-city temporal skill alone, on a variance that is ~17× smaller for temperature and ~6× smaller for humidity than the pooled variance.

R²_anom — within-city skill vs. a per-city climatological mean, computed by removing each city's own mean from both truth and prediction before scoring. Reported per model in full_results_report.json under the key *_r2_anom. This is a distinct quantity and must be labelled as such.

**The old `indian_weather_pipeline_v3_final.py` is now listed in the repository-contents table** as the previous version, retained for provenance. This matters: the reviewer may have the old file open alongside the new one, and the README should make it clear which is which and that the old file reproduces the pre-correction numbers. Otherwise it looks like the ARIMA was fixed in place and the reviewer may wonder why the old file still produces 0.069.

**The changelog section title** was rewritten from "What changed in Revision 4" to "What changed relative to `indian_weather_pipeline_v3_final.py`", since the filename no longer carries a version number that distinguishes it from the old one.

**No numbers changed.** The results tables, walk-forward, LOCO, multi-step, and improvement-over-persistence blocks all match the run output you provided (`temp_r2=0.9327` persistence, `temp_r2=0.9258` ARIMA pooled, `temp_r2=0.9330` stacked, LOCO medians 0.8169 / 0.8322, multi-step 0.7777 / 0.0342 / −0.7901 / −1.9117). ## One thing worth deciding before you send this

The filename `indian_weather_pipeline_v3_arima_fixed.py` names the ARIMA correction explicitly, but the pipeline also made a substantive change to the persistence baseline. A reviewer reading the filename might assume the only change was ARIMA and be surprised when the persistence numbers also moved (0.817 → 0.933). Two options:

- **Rename to something neutral** like `indian_weather_pipeline_v3_corrected.py` or `indian_weather_pipeline_v4.py`, so the filename does not single out one of the two corrections.
- **Keep the current filename** and lean on the changelog section to make clear that both corrections are documented. The current README already does this — Change 1 and Change 2 are labelled separately — so this is defensible.

Either is fine. The README as written works for both, since it references the filename only as an identifier and explains the content changes in prose.
