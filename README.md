# IndianTemp_Hum – Stacked Ensemble Forecasting for Temperature and Humidity

**Multi-Location Temporal Forecasting of Near-Surface Temperature and Relative Humidity Across Diverse Climatic Regions of India**

This repository contains the complete, reviewer-responsive pipeline used to produce the results reported in `Methodology_Report.docx`. It resolves all eleven major review comments from the three review rounds; see Section 7 of the report for the full comment-by-comment crosswalk.

The pipeline file `indianweather files/indian_weather_pipeline_v3_arima_fixed.py` is the current version and includes the two corrections made in response to the most recent review round: the graphical-abstract inconsistency and the ARIMA baseline anomaly. A summary of what changed relative to the earlier `indian_weather_pipeline_v3_final.py` is provided in the [Changelog](#what-changed-relative-to-indian_weather_pipeline_v3_finalpy) section below.

## Execution Instructions (Reviewer Comment 8)

The full pipeline is compute-intensive. Per-city ARIMA order search and true leave-one-city-out evaluation across all 543 locations together take on the order of 20–45 minutes on a standard CPU (longer than the previous pipeline, because the extended feature set and per-city bias-correction step add work).

### Full run (single command)

```bash
python "indianweather files/indian_weather_pipeline_v3_arima_fixed.py"
```

This runs every stage in sequence:

1. Data validation
2. Feature engineering
3. Per-city persistence
4. Stacked ensemble with bias correction
5. Walk-forward validation
6. Corrected ARIMA
7. LSTM
8. Full 543-city LOCO
9. SHAP
10. Residuals
11. Multi-step recursive forecasting
12. Per-location tables with bootstrap CIs
13. Study-city figures

Outputs are written to `csv files/`, `visualisation/`, and `model_artifacts/`.

### Quick smoke test

For a fast verification (fewer ARIMA/LOCO cities and fewer LSTM epochs, so minutes instead of tens of minutes), set `fast_smoke_test=True` inside the `main()` call at the bottom of `indianweather files/indian_weather_pipeline_v3_arima_fixed.py`:

```python
if __name__ == "__main__":
    main(fast_smoke_test=True)
```

This is intended to confirm that the pipeline runs end-to-end without error before committing to a full reported run. The resulting numbers will differ from the results below and **should not be cited as reported results**. Set it back to `False` (the default) to reproduce the numbers in `Methodology_Report.docx`.

## What Changed Relative to `indian_weather_pipeline_v3_final.py`

The ARIMA-corrected pipeline was produced in direct response to the two outstanding points in the most recent review round. Two substantive changes were made; both are documented in more detail in Section 7 of the report.

### Change 1 – Fair ARIMA evaluation

*(Responds to "ARIMA needs investigation/clarification".)*

The previous ARIMA result (Temp R² = 0.069, Hum R² = −0.061) was an evaluation artefact, not a property of ARIMA on this data. Two problems existed in the old pipeline:

1. ARIMA was fitted and evaluated on the raw per-city series with its own train/test split, which did not coincide with the split used by persistence, LSTM, and the stacked ensemble.
2. The aggregate ARIMA metric was reported as the mean of per-city R² values, whereas persistence and the stacked ensemble were reported as pooled R² over the full held-out set. Averaging R² across 543 cities, many of which have short, low-variance test windows, biases the aggregate sharply downward even when the underlying predictions are of comparable quality.

ARIMA is now evaluated on exactly the same held-out rows as every other model (the train/test boundary is defined by intersecting each city's series with the same test index used downstream), and its metrics are reported pooled over those rows, in original physical units (°C and %RH). Row-level predictions with `city`, `datetime`, `y_true`, and `y_pred` are saved so the alignment can be verified independently.

After the correction:

- Temperature R² rises from 0.069 → **0.926**
- Humidity R² rises from −0.061 → **0.797**

These values are comfortably in line with the persistence and stacked-ensemble baselines; ARIMA is the best model on humidity R².

### Change 2 – Fair persistence baseline

The previous persistence baseline used a single global `shift(1)` on the concatenated multi-city test set, which for the first row of each city predicted from the last row of a different city. That cross-city contamination made persistence look artificially worse than it should.

In the corrected pipeline, persistence is computed per-city (`ŷ_t = y_{t-1}` within the same city). The corrected persistence MAE is therefore stronger, **0.783 °C instead of 1.009 °C**, which is why the stacked ensemble no longer shows a large MAE advantage over persistence. This is an honest correction; the manuscript now states plainly that the stacked ensemble matches but does not beat per-city persistence on temperature MAE, and that its advantage over ARIMA is confined to a small RMSE reduction on temperature.

### Additional improvements

Three further improvements were also made to the feature set and modelling pipeline:

- **(a) Extended temporal features:** lags 1–8, rolling means/stds over 24 h and 48 h, 24-hour change, and lagged atmospheric covariates.
- **(b) Per-city additive bias correction:** fitted on a chronological validation slice and shrunk toward zero.
- **(c) Three clearly labelled R² definitions** reported side by side: pooled, per-location with bootstrap CIs, and R²<sub>anom</sub> (a within-city skill score against a per-city climatological mean).

The three-way R² distinction is what prevents a recurrence of the graphical-abstract mismatch flagged in the previous review round.

## Results Summary

Full per-fold, per-city, and per-horizon tables underlying every number below are written as CSV files to `csv files/` by `indianweather files/indian_weather_pipeline_v3_arima_fixed.py` (walk-forward results, per-city ARIMA order/AIC/accuracy, per-location LOCO results, per-location R² with bootstrap CIs, ARIMA row-level predictions, and multi-step MAE/RMSE/R² by horizon), alongside every figure placed in `visualisation/`.

### Main comparison table

All models evaluated on the **same 8,742 held-out rows**, in original units.

| Model | Temp R² | Temp MAE (°C) | Temp RMSE (°C) | Hum R² | Hum MAE (%) | Hum RMSE (%) |
|:------|--------:|--------------:|---------------:|-------:|------------:|-------------:|
| Persistence (per-city, corrected) | 0.933 | 0.783 | 1.187 | 0.777 | 5.761 | 8.568 |
| ARIMA (pooled, corrected) | 0.926 | 0.880 | 1.247 | 0.797 | 5.699 | 8.168 |
| LSTM | −0.683 | 4.266 | 5.938 | −0.270 | 16.587 | 20.438 |
| Stacked Ensemble | 0.933 | 0.802 | 1.184 | 0.787 | 6.320 | 8.367 |

**Reading of the corrected table.** ARIMA is within 0.007 R² of the stacked ensemble on temperature and is the best model on humidity R², marginally ahead of both persistence and the stacked ensemble. Persistence, which is now computed per-city rather than globally, is a strong baseline on this dataset (as expected for a highly autocorrelated ~6-hourly series), and neither ARIMA nor the stacked ensemble beats it by more than a small RMSE margin on temperature. The LSTM's negative R² reflects a target-variance effect at this cadence and test-set size, not a contradiction; the manuscript discusses this in Section 6 of the report.

### Three complementary R² definitions

Three R² definitions are reported side by side because they answer different questions on different denominators. They are not interchangeable, and the manuscript labels each explicitly.

| Definition | Description |
|:-----------|:------------|
| **Pooled R²** | Evaluated on the full held-out set (main comparison table above). Reflects both cross-city climatic separation and within-city temporal skill. |
| **Per-location R²** | Within-city R², reported with 95 % bootstrap CIs, in `per_location_*_temp.csv` / `per_location_*_hum.csv` and their `*_study_cities.csv` subsets. Reflects within-city temporal skill alone, on a variance that is ~17× smaller for temperature and ~6× smaller for humidity than the pooled variance. |
| **R²<sub>anom</sub>** | Within-city skill versus a per-city climatological mean, computed by removing each city's own mean from both truth and prediction before scoring. Reported per model in `full_results_report.json` under the key `*_r2_anom`. This is a distinct quantity and must be labelled as such. |
